# Solpient 100 Universe Screening Engine\n\n## Objective\n\nThe universe screen answers one question:\n\n> Which companies are worth spending expensive Solpient research effort on?\n\nIt does **not** answer whether a stock should be bought today. Phase 3 Decision Ranking remains the post-research decision layer.\n\n## Pipeline\n\nLarge normalized universe\n→ investability/distress gates\n→ sector-aware quantitative scoring\n→ evidence coverage\n→ Research Candidate / Solpient 100 Candidate\n→ deep fundamental research\n→ reviewed Solpient 100 membership\n\nFinal membership is never created automatically by the broad screen.\n\n## States\n\n- **Excluded** — fails a hard investability, distress, leverage, or profile-specific gate.\n- **Watch** — investable but evidence or score is not strong enough for deep research yet.\n- **Research Candidate** — merits deeper work.\n- **Solpient 100 Candidate** — high-quality, sufficiently complete candidate for the curated universe.\n- **Solpient 100** — only when an explicit reviewed membership flag is supplied.\n\n## Buffett/Lynch weighting\n\nThe screen deliberately keeps valuation from dominating business quality.\n\nDefault profile weights:\n\n- Business Quality: 35%\n- Durability / consistency: 20%\n- Balance sheet: 15%\n- Growth: 15%\n- Valuation: 15%\n\nSector profiles adjust those weights slightly. Software gives somewhat more weight to quality/growth; utilities and cyclicals give more weight to durability/balance sheet.\n\nCheap junk therefore cannot screen into the Solpient 100 merely because P/E or EV/EBITDA is low.\n\n## Hard gates\n\nThe default core universe requires:\n\n- minimum market capitalization\n- minimum 30-day average dollar volume\n- minimum share price\n- no bankruptcy/restructuring flag\n- no going-concern flag\n- no extreme corporate leverage for applicable profiles\n\nProfile thresholds differ by sector. Mature biopharma additionally requires commercial-scale revenue.\n\nThese are research-universe gates, not universal claims about what makes a security investable for every strategy.\n\n## Sector profiles\n\nV1 includes:\n\n- general\n- software\n- consumer\n- industrial\n- healthcare / medtech\n- mature biopharma\n- financial / bank\n- REIT\n- utility\n- cyclical / energy / materials\n\nFinancials are not penalized by corporate net-debt/EBITDA rules. Banks instead use sector-relevant fields such as ROE, efficiency ratio, CET1, tangible common equity, liquidity coverage, book-value growth, P/TBV and forward P/E.\n\nREITs can use AFFO margin/growth, leverage, fixed-charge coverage and P/AFFO.\n\n## Missing data\n\nMissing metrics are never converted to 50.\n\nEach dimension is scored over the evidence actually available and carries its own coverage percentage. Overall evidence coverage weights those dimension coverages using the profile's intended model weights.\n\nLow evidence coverage forces a company to Watch even if the available metrics look strong.\n\n## Score thresholds\n\nAfter hard gates:\n\n- evidence coverage below 55% → Watch\n- score >=60, quality core >=60, coverage >=60% → Research Candidate\n- score >=75, quality core >=72, coverage >=70% → Solpient 100 Candidate\n\nApproved existing members can retain the Solpient 100 state when coverage and quality remain above maintenance floors; deterioration should be reviewed rather than silently deleting membership.\n\n## Selection\n\n`selectSolpient100Candidates()` ranks the eligible research universe deterministically by:\n\n1. screening state\n2. total screen score\n3. quality-core score\n4. evidence coverage\n5. ticker\n\nThe top `N` eligible rows can be proposed for deep research. The default `N` is 100.\n\n`proposedForDeepResearch=true` is **not** final membership.\n\n## Normalized input contract\n\nEvery row must contain a unique ticker. Broad providers should normalize their fields to the names below where available.\n\n### Identity / investability\n\n- `ticker`\n- `company_name`\n- `sector`\n- `industry`\n- optional `screen_profile` override\n- `market_cap`\n- `avg_dollar_volume_30d`\n- `price`\n- `bankruptcy_flag`\n- `going_concern_flag`\n\n### Quality\n\n- `roic`\n- `roe`\n- `fcf_margin`\n- `cash_conversion_pct`\n- `operating_margin`\n\n### Durability\n\n- `positive_fcf_years`\n- `positive_eps_years`\n- `positive_revenue_growth_years`\n- `operating_margin_volatility_pct`\n- `share_dilution_3y_pct`\n\n### Balance sheet\n\n- `net_debt_to_ebitda`\n- `debt_to_equity`\n- `interest_coverage`\n- `current_ratio`\n\n### Growth\n\n- `revenue_growth_3y_cagr`\n- `eps_growth_3y_cagr`\n- `fcf_growth_3y_cagr`\n\n### Valuation\n\n- `price_to_fcf`\n- `forward_pe`\n- `ev_to_ebitda`\n- `peg_ratio`\n- `fcf_yield_pct`\n\n### Financial-sector optional fields\n\n- `efficiency_ratio`\n- `nonperforming_assets_pct`\n- `positive_book_value_growth_years`\n- `credit_loss_volatility_pct`\n- `cet1_ratio`\n- `tangible_common_equity_ratio`\n- `liquidity_coverage_ratio`\n- `payout_ratio`\n- `book_value_growth_3y_cagr`\n- `price_to_tangible_book`\n\n### REIT optional fields\n\n- `affo_margin`\n- `affo_growth_3y_cagr`\n- `fixed_charge_coverage`\n- `price_to_affo`\n\n### Mature-biopharma gate\n\n- `revenue_ttm`\n\nProviders do not need to supply every field. Missing fields reduce evidence coverage.\n\n## File formats\n\n`scripts/run-universe-screen.mjs` supports:\n\n- JSON array\n- JSON object with a `securities` array\n- JSONL / NDJSON\n\nOptional object metadata:\n\n- `provider`\n- `as_of_at`\n- `source_version`\n- `universe_name`\n\nUse `--dry-run` to inspect ranking/states before materialization.\n\n## Historical integrity\n\nUniverse screen batches and result rows are append-only.\n\nThe input hash includes methodology version, selection version, provider, as-of timestamp, shortlist limit and normalized rows. Identical input hashes do not create duplicate batches.\n\nBroad-screen history is kept separate from published research history so later research does not retroactively rewrite why a company originally entered the research funnel.\n\n## Phase 2 isolation\n\nV1 does not consume Phase 2 provenance or publication tables. After Phase 2 stabilizes, a future methodology version can use provenance quality as an additional screening-evidence signal without changing historical V1 screens.

## Staged immutable publication V1.2

Full-universe result payloads can exceed practical Data API request limits when every scored issuer is sent in one RPC request.

Production materialization therefore uses a staged transport:

1. `begin_universe_screen_publish_v1_2()` creates or resumes an idempotent service-role-only staging session.
2. The CLI sends bounded result chunks (maximum 25 rows and approximately 180 KB by default).
3. Each chunk is idempotent by session + ordinal and rejects conflicting retries.
4. `finalize_universe_screen_publish_v1_2()` verifies that ordinals 1..N are complete.
5. PostgreSQL then inserts the immutable `universe_screen_runs` row and every `universe_screen_results` row in one transaction.
6. Staging rows are deleted only after successful finalization.

A transport failure before finalization can leave only ephemeral staging data. It cannot create a partial immutable screen run. Re-running the same materializer resumes the same staging session and safely retries transient 520/502/503/504 or network failures.
