# Solpient 100 Daily Analysis + Score V1\n\n## Goal\n\nMaintain one governed research and scoring loop for all 100 companies with one daily command.\n\n```text\nnpm run daily:100\n```\n\nThe existing macOS scheduler also runs the same `run-solpient-daily.mjs` entrypoint, so the daily architecture stays single-entry rather than creating 100 jobs.\n\n## Daily flow\n\n```text\nGoverned immutable Solpient 100\n  -> SEC Companyfacts check for the 100\n  -> market-price/history refresh for the 100\n  -> autonomous research refresh\n       -> rebuild only companies with changed durable evidence\n       -> stage changed analysis privately in /review\n  -> private Phase 3 score refresh for all 100\n  -> released/public Phase 3 ranking refresh\n  -> Solpient 100 / 20 / 5 refresh\n```\n\n## One score methodology\n\nThere is no second investment-ranking score.\n\nBoth private and public scoring use:\n\n- `decision-ranking-v1`\n- Business Quality\n- Investment Opportunity\n- Evidence Confidence\n- Decision Score\n- Building / Research Ready / Decision Ready\n\nBefore release, the same Phase 3 result is stored in the private `solpient_100_daily_scores` ledger and shown only in `/review`.\n\nAfter release, the immutable published research run remains the public source and the existing `ranking_history` ledger is refreshed from it.\n\n## Update semantics\n\n### Every day\n\n- current price / market history updates\n- valuation gap and opportunity score recalculate\n- evidence/readiness and Solpient Score refresh for all 100\n- rankings can move even when the underlying research text does not change\n\n### Only when durable evidence changes\n\n- historical/peer context rebuilds\n- baseline analysis rebuilds\n- Composer V2 research package regenerates\n- a new private `/review` package is staged\n\nDurable evidence includes new/restated normalized fundamentals and sector-assignment changes. A market-price move alone does not regenerate qualitative research.\n\n## SEC no-churn rule\n\nThe SEC Companyfacts worker now fingerprints normalized fundamental rows. Existing identical facts are not rewritten with a new `observed_at`. This prevents all 100 companies from falsely appearing changed every morning.\n\n## Private/release boundary\n\nUnreleased analysis and scores stay private in `/review`.\n\n`/review` shows:\n\n- private daily rank\n- Solpient Score\n- Evidence Confidence\n- readiness state\n- analysis/review status\n\nHuman review remains the publication boundary. Daily automation never verifies or releases research.\n\n## First-time setup\n\nApply the private score-ledger migration once:\n\n```bash\nnpm run local:migrate:daily-score\n```\n\nThen run tests:\n\n```bash\nnpm run test:daily-score100\nnpm run test:baseline-factory100\nnpm run test:baseline-contract\nnpm run test:composer\n```\n\nInspect the daily plan without writes:\n\n```bash\nnpm run local:daily:dry-run\n```\n\nRun the entire daily update manually:\n\n```bash\nnpm run daily:100\n```\n\nOr install/reinstall the existing launchd schedule:\n\n```bash\nnpm run local:scheduler:install\n```\n\nThe scheduler defaults to 06:30 Mac local time.\n\n## Expected behavior while coverage is still incomplete\n\nThe private daily ledger always contains the governed 100. Companies that still lack enough evidence are marked `building` and may have a null Decision Score instead of receiving a fabricated neutral score.\n\nThe daily run reports `scored` and `unscored` counts. The research factory continues filling those gaps. Once adequate evidence exists, the same Phase 3 methodology produces the score automatically.\n\n## Public release\n\nDaily automation does not publish.\n\nUse `/review` to verify packages and then `Release all verified`. After release, public company pages and public Phase 3 ranking use the immutable published research packages.\n
